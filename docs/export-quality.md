# 导出质量规则

这些规则用于区分图片像素、显示大小和文档结构。保存成功表示文件已生成；清晰度还取决于页面实际提供的内容，不能从低清位图恢复原本没有的细节。

| 内容 | 采集与保存规则 | 格式边界 |
| --- | --- | --- |
| 普通图片 | 等待当前块内唯一、可见的图片加载稳定，读取已解码位图的实际像素，输出 PNG；源、节点或分辨率变化后复核并更新 | 不额外请求原图，不改写资源 URL。PNG 是页面已解码画面的无损保存，不等同于取得上传原件 |
| 高像素密度图片 | 优先使用 ImageBitmap 的实际位图尺寸，避免把 `2x` 资源按经过密度修正的 `naturalWidth` 缩小 | 不支持 ImageBitmap 的环境回退为浏览器已加载图片的尺寸 |
| 飞书画板 | 仅取明确的内容层，排除辅助控件；已知嵌入视图优先通过本地尺寸调整触发原生重绘，目标为每个 CSS 像素至少两个真实像素，受资源上限约束 | 完成、失败或取消都恢复本地样式。原生重绘不可用时保留可读预览；不直接放大原 Canvas。只表示当前预览，不承诺无限画布全量或矢量、可编辑导出 |
| Markdown、HTML、素材包 | 保留已采集图片字节；HTML 内嵌，Markdown 相对引用，素材包提供独立文件 | HTML 按阅读窗口缩小显示，不减少文件中的像素；Markdown 阅读器的显示大小取决于阅读器 |
| PDF 图片 | 无需切片的静态 PNG、JPEG 保留已采集资产原字节；GIF、WebP 以原尺寸转静态 PNG；不统一压缩到固定最长边 | 长图按整数像素行连续切片，以正文或所属单元格的可用宽度等比排版，页间不漏行、不重复行；分段会有提示 |
| 正文表格 | 保留文字、链接、强调、删除线、表题、语义表头及行组、跨行跨列结构；读取列宽比例、底色、对应文字色及水平/垂直对齐 | HTML 保留列宽比例，长串文字在格内换行；PDF 优先使用源比例、缺失时自适应，语义表头跨页重复；极宽表按行展开并提示；带样式或结构复杂的 Markdown 表格使用 HTML |

列宽来自原生列轨道，无法读取时只使用可确认的完整无合并行，不平均分摊合并格猜列宽。底色按计算样式逐层合成透明图层；深色格内的代码、引用和链接继承可读前景色。隐藏的合并占位格不作为额外单元格导出。分离渲染的固定表头与正文合并，重复表头只保留一次；原生表头语义进入 thead，PDF 可跨页重复。只保留有限数值、规范色值和对齐枚举，不复制任意 CSS。

表格按目标格式重新排版。PDF 按纸张宽度缩放列轨道，过窄列保留最低可读宽度；单元格自身内容跨页时，引擎会将垂直居中/底部对齐退回顶部流式排版。单元格内多个段落对齐不同的情况使用该格默认对齐，不任选一段覆盖其余段落。固定行高、边框样式和广色域计算色等尚未逐项复刻。DOM 未提供的语义表头不会仅凭颜色推断。表格中的图片仍遵守图片规则，文字保持文字。

带样式的 Markdown 表格依赖阅读器允许 HTML 和内联样式；阅读器过滤样式时，外观可能降级。HTML 文件可直接在浏览器中核对。

单图继续限制在 8192 像素单边、1600 万像素以内；PDF 另有总像素、输入字节和输出字节上限。超限明确报错或提示，不通过悄悄降低分辨率来掩盖问题。原始 SVG 不直接放行进入导出 HTML。

## 核对方法

1. 先核对素材图片的真实像素尺寸，再核对 HTML、Markdown 使用的图片字节是否一致。
2. 在图片原尺寸与常用阅读比例下检查细线、小字和透明背景；更大文件或更多像素本身不足以证明清晰度提升。
3. PDF 实际保存后检查嵌入图片尺寸、分片顺序和分页，并渲染各页检查可读性与裁切。
4. 表格检查表题、行列数、合并关系、单元格文字和删除线；跨页检查重复表头，宽表检查是否溢出或明确降级。
5. 连续导出时核对图片和文本一致，确认原页面显示尺寸及阅读位置恢复。

浏览器位图尺寸依据 [WHATWG ImageBitmap](https://html.spec.whatwg.org/multipage/imagebitmap-and-animations.html#dom-createimagebitmap)；PDF 的图片等比布局与表头行为依据 [pdfmake Images](https://pdfmake.github.io/docs/0.3/document-definition-object/images/) 和 [pdfmake Tables](https://pdfmake.github.io/docs/0.3/document-definition-object/tables/)。这些 API 行为不构成对所有文档和浏览器的验证承诺。
